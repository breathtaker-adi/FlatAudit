Things to correct or tighten

  • Spike thresholds are too loose. With only 5 observations per window, a median swings widely. Instead of a fixed “+12% with n ≥ 5”, test whether the recent and baseline medians differ beyond random noise, for example with a bootstrap interval, and require a larger minimum sample. Tune on simulated spikes before trusting it.
  • RBI coverage is out of date in the text. The latest index covers 18 cities with 2022-23 as the base year, not 10. Pull the city list and the figures from the published series, and never hard-code an example like “+4.2% YoY”.
  • Unverified claims in docs: provider pricing (“thousands of dollars per month”), the 5 MB storage figure, and “no free API exists” should be worded as “I found none” and checked before they go in the README.
  • Pilot data: confirm every project, guidance value and cost rule has a source URL and a verified date, or hide it.
  • Name the sources of “aggressively block scrapers”. Keep claims about portals factual and limited to what you tested.

Spike check: a better test

Do

  • Compare recent and baseline medians with an interval, not a fixed percentage
  • Require a minimum sample in both windows, set from simulation
  • Confirm with repeat-listing changes
  • Stratify by BHK and area type
  • Report a range and sample sizes in plain words

Avoid

  • Announcing a spike from a handful of listings
  • Letting one contributor or one new building move the median
  • Flagging listings more often during a market move
  • Mixing index values and listing prices

Scope guard

You’re building a portfolio project with real depth already. If time gets tight, stop after Rajasthan plus one more state, finish Stage 6, and move extra states, Firefox, a text model and a mobile path to a v1.3 list. A smaller product with measured accuracy beats a wide one with unverified data.
