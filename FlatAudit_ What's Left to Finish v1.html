Plan to finish (about 5 weeks)

Rule: freeze features. No new capabilities until the checklists below are done. Anything new goes on a “v1.1” list.

Week 1: Live-page reality check

find what breaks
  • Make a test matrix: each portal × listing page, results page and similar-listings section
  • Load the extension on real pages in at least 3 cities and note every failed or empty field
  • Save those pages as new fixtures with personal details removed; fix the parsers
  • Add a health test that fails when a parser returns empty rent, BHK or locality
  • Check performance: no visible lag, no repeated requests, no errors in the console
Done when: at least 90% of the pages you try produce a correct badge, and failures show a calm “couldn’t read this page” message.

Week 2: Real labels and honest metrics

the most important week
  • Label 150+ real listings from at least 5 cities, with a mix of obviously normal and suspicious ones
  • Keep labels private; commit only a schema and a handful of sanitized examples
  • Run evaluate.py on the real set; report precision, recall, per-city results and false positives
  • Fix rules for the biggest misses; keep a held-out city you never tune on
  • Rename the synthetic set “unit-test data” everywhere, including docs and the demo
Done when: the README’s headline metric comes from real listings and states how many and from where.

Week 3: Harden and deploy

safe to put in other people’s hands
  • Update threat-model.md for market packs, the host permission and local storage of watchlist data
  • Audit permissions and justify each one in the README
  • Validate pack JSON in the extension before use; ignore anything malformed
  • Make the API URL a setting, not hard-coded to localhost; restrict CORS to your own origins
  • Deploy the backend on a free tier; host packs as static files; run npm audit and pip-audit
  • Write a plain privacy policy and a short note on each portal’s Terms of Service
Done when: someone else’s browser can use your deployed API and nothing sensitive leaves the browser.

Week 4: People test it

fix what confuses them
  • Recruit 5–10 people actually looking for rentals, ideally in different cities
  • Watch or ask: Do they understand the badge? Do they trust it? Do they use Track?
  • Add a small “this looks wrong” feedback link and read every response
  • Fix the top 5 usability problems; remove anything nobody uses
  • Check wording: observable facts only, never “scam” or “fraud” about a person
Done when: at least 5 people used it for a week and you have notes on what they liked and ignored.

Week 5: Ship and tell the story

make it reviewable
  • Icons, screenshots and a clear store description; publish to the Chrome Web Store as unlisted
  • README: what it does, install, privacy, real metrics, known limits
  • 2-minute demo video and a clean architecture diagram
  • Blog post: what worked, what failed on real data, what you’d change
  • Tag v1.0, add a license, check no private data or secrets are in git history
Done when: a stranger can install it and a reviewer can understand the project in five minutes.

Definition of done for v1

  • Real-listing metrics published, with per-city results and honest limits
  • Parsers tested on live pages from several cities, with a health check
  • Deployed backend, configurable URL, validated packs
  • Updated threat model, privacy policy and permission justifications
  • Used by at least 5 real people for a week
  • Public repo, demo video and write-up

After v1 (v1.1 list, not now)
